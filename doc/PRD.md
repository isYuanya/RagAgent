# PRD: RagAgent V1 文案资产闭环

## 1. 背景

RagAgent 是一个面向短视频/口播文案的 Agent + RAG 项目。长期目标是让系统能够理解文案、沉淀模板、检索知识、生成内容、进行合规评审，并通过反馈持续优化。

当前第一阶段不追求完整自动生成闭环，而是先建立高质量文案资产库。原因是：如果没有稳定、可校正、可复用的文案资产，后续 RAG 检索、模板生成、策略层和反馈优化都会缺少可靠基础。

## 2. V1 目标

V1 要完成“批量导入 -> LLM 拆解 -> 人工校正 -> 资产沉淀”的闭环。

核心目标：

- 能批量导入已有短视频/口播文案。
- 能调用 LLM 将文案拆解成结构化字段。
- 能展示导入进度、调用状态、使用模型和行级错误。
- 能让用户人工校正拆解结果。
- 能保存校正后的文案资产，作为后续检索和生成的基础数据。

V1 成功的标志不是“生成文案效果已经最好”，而是“文案资产能被稳定导入、拆解、校正和复用”。

## 3. 目标用户

当前目标用户是项目作者或内部使用者。

用户特点：

- 能接受本地部署和手动启动服务。
- 能接受对 LLM 拆解结果做人工校正。
- 更关注文案资产质量，而不是外部产品化体验。
- 希望后续可以让 Agent 基于这些资产继续生成、评审和优化内容。

暂不面向外部多用户团队或公开 SaaS 用户。

## 4. 使用场景

用户已经收集了一批高表现短视频/口播文案，希望把这些文案沉淀成结构化资产。

典型流程：

1. 用户整理 CSV，包含原文、来源、发布平台、作者、粉丝数、行业、人群、目标、风格和表现指标。
2. 用户在前端上传 CSV。
3. 系统逐行调用 LLM 拆解文案。
4. 前端展示导入进度、使用模型、成功数量、失败数量和错误行。
5. 用户查看每条文案的原文和自动拆解结果。
6. 用户校正主题、痛点、钩子、结构、模板、风险等字段。
7. 用户保存校正结果。
8. 系统将这些资产用于后续模板库、检索库和生成流程。

## 5. V1 范围

### 5.1 包含

- CSV 批量导入文案资产。
- LLM 自动拆解文案。
- 导入任务状态和进度展示。
- 文案资产列表和详情。
- 原文、元数据、表现指标展示。
- 拆解结果人工校正。
- 审核状态保存。
- 行级错误提示。

### 5.2 不包含

- 网页链接自动抓取文案。
- 多用户、权限、团队协作。
- 账号风格自动学习。
- A/B 测试和发布数据自动回流。
- 完整 LangGraph 策略编排。
- 高级 RAG 排序和向量检索优化。
- 对外商业化工作台。

这些能力进入后续路线图，不阻塞 V1。

## 6. 核心功能需求

### 6.1 CSV 导入

系统应支持用户上传 CSV 文件。V1 约定字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `source_text` | 是 | 原始文案 |
| `source_url` | 否 | 文案来源链接 |
| `author_name` | 否 | 发布作者或账号名称 |
| `author_url` | 否 | 发布作者主页链接 |
| `author_follower_count` | 否 | 作者粉丝数 |
| `platform` | 否 | 平台，如小红书、抖音、视频号 |
| `industry` | 否 | 行业或赛道 |
| `audience` | 否 | 目标人群 |
| `purpose` | 否 | 内容目标，如引流、成交、涨粉 |
| `style` | 否 | 表达风格 |
| `likes` | 否 | 点赞数 |
| `comments` | 否 | 评论数 |
| `favorites` | 否 | 收藏数 |
| `shares` | 否 | 转发数 |

导入要求：

- `source_text` 为空的行不能导入。
- `author_follower_count` 如果存在，必须能解析为非负整数。
- 指标字段如果存在，必须能解析为整数。
- 单行失败不应影响其他有效行。
- 前端应展示行级错误。

### 6.2 LLM 拆解

系统应对每条有效文案调用 LLM，输出结构化拆解结果。

拆解字段：

| 字段 | 说明 |
| --- | --- |
| `topic` | 文案主题 |
| `target_user` | 目标用户 |
| `core_pain` | 核心痛点 |
| `emotion_buttons` | 情绪按钮，如好奇、焦虑、共鸣、危机感 |
| `hook` | 开头钩子 |
| `structure` | 内容结构步骤 |
| `expression_skills` | 表达技巧 |
| `reusable_template` | 可复用模板或句式 |
| `suitable_scenarios` | 适用场景 |
| `risk_warnings` | 风险提醒 |
| `confidence` | 拆解置信度，范围 0 到 1 |

LLM 返回内容必须被后端校验。对于常见格式偏差，例如把列表字段返回成字符串，后端可以做安全归一化，但对外 API 仍应返回稳定的结构化字段。

### 6.3 导入任务进度

CSV 导入是批量 LLM 调用，前端必须能看到任务状态。

任务状态至少包含：

- 当前阶段：等待、解析 CSV、调用 LLM、保存资产、完成、失败。
- 使用模型。
- 当前行。
- 总行数。
- 已处理数量。
- 成功数量。
- 失败数量。
- 百分比进度。
- 当前状态说明。
- 行级错误。

### 6.4 文案资产列表

导入成功后，用户应能在资产列表中看到文案资产。

列表至少展示：

- 主题或原文摘要。
- 作者名称。
- 平台。
- 行业。
- 审核状态。

资产列表应支持后续扩展筛选，例如按平台、行业、审核状态筛选。

### 6.5 文案资产详情和校正

用户点击某条资产后，应看到：

- 原始文案。
- 来源链接。
- 作者名称、作者主页和粉丝数。
- 平台、行业、人群、目标、风格。
- 点赞、评论、收藏、转发等表现指标。
- LLM 自动拆解结果。
- 人工校正字段。

用户应能校正以下核心字段：

- 主题。
- 目标用户。
- 核心痛点。
- 情绪按钮。
- 开头钩子。
- 内容结构。
- 表达技巧。
- 可复用模板。
- 适用场景。
- 置信度。
- 审核状态。

### 6.6 审核状态

V1 至少支持三种审核状态：

- `pending_review`：待审核。
- `approved`：已确认。
- `rejected`：已拒绝。

默认导入成功后的资产状态为 `pending_review`。

## 7. 数据对象

### 7.1 CopySource

表示原始文案资产。

核心字段：

- 文案 ID。
- 原文。
- 来源链接。
- 平台。
- 行业。
- 目标人群。
- 内容目的。
- 表达风格。
- 表现指标。
- 创建时间。

### 7.2 CopyAnalysis

表示文案拆解结果。

核心字段：

- 所属文案 ID。
- 自动拆解结果。
- 人工校正结果。
- 置信度。
- 审核状态。
- 创建时间或更新时间。

### 7.3 Author

表示文案发布作者或平台账号。

V1 只随文案资产保存作者基础信息，不单独做作者分析。

核心字段：

- 作者名称。
- 作者主页链接。
- 所属平台。
- 粉丝数。
- 关联文案数量。

### 7.4 ImportTask

表示一次 CSV 导入任务。

核心字段：

- 任务 ID。
- 任务状态。
- 使用模型。
- 当前阶段。
- 当前行和总行数。
- 成功数量和失败数量。
- 行级错误。
- 完成结果。

## 8. 非功能需求

- 本地可运行，优先服务个人开发和验证。
- 导入任务不能长时间阻塞前端页面。
- LLM 调用失败时，错误必须可见。
- CSV 编码应优先兼容 UTF-8 和 UTF-8 BOM。
- 后端 API 返回结构应稳定，前端不直接依赖 LLM 原始输出。
- 文案资产应进入可共享存储，避免 worker 和 API 进程之间数据不可见。
- 作者信息应作为后续作者分析的基础数据保留。
- 测试环境不能依赖真实 LLM 网络调用，应使用 mock 或 fake。

## 9. 成功标准

V1 完成时，必须满足：

- 用户可以上传测试 CSV。
- 前端能显示导入任务进度和使用模型。
- 合法文案会逐条完成 LLM 拆解。
- 无效行会显示行级错误，不影响其他行。
- 导入成功的资产能显示在列表中。
- 用户能查看原文、作者、平台、元数据、指标和拆解结果。
- 用户能校正拆解字段并保存审核状态。
- 后端测试通过。
- 前端构建通过。

## 10. 技术约束

PRD 不规定完整实现细节，但 V1 需要遵守以下约束：

- 后端使用 FastAPI。
- 前端使用 React 工作台。
- LLM 使用 OpenAI 兼容接口。
- 批量任务使用 Redis + RQ 或兼容兜底机制。
- 结构化数据优先进入 PostgreSQL；本地开发可保留 Redis/内存兜底。
- 后续 RAG、LangGraph、Milvus 可以预留边界，但不作为 V1 验收前提。

更详细的工程结构和技术边界见 `doc/PROJECT_STRUCTURE.md`。

## 11. Roadmap

### V1.1 模板库抽象

- 从已审核文案中抽取结构模板、钩子模板、情绪路径和转化方式。
- 支持按行业、目的、人群筛选模板。

### V1.2 RAG 检索接入

- 将已审核文案、模板和标签写入检索索引。
- 生成前检索相似案例、模板和禁用表达。

### V1.3 文案生成增强

- 基于产品、人群、目的、风格生成多个方向。
- 支持参考文案和模板约束。
- 输出标题、钩子、口播正文、分镜建议和评论区引导。

### V1.4 评审和合规

- 增加原创性检查。
- 增加敏感词和夸大承诺检查。
- 增加人工 + Agent 多轮筛选。

### V1.5 反馈回流

- 记录用户选择、评分和修改。
- 引入发布数据，如点赞、评论、收藏、转发。
- 用反馈优化检索和生成策略。

### V1.6 作者分析

- 按作者聚合文案资产、粉丝数和表现指标。
- 分析作者常用选题、钩子、结构、表达技巧和风险偏好。
- 对比同平台不同作者的内容策略差异。

## 12. Open Questions

- 文案资产最终以 PostgreSQL 为唯一主存储，还是保留 Redis 缓存作为本地常驻兜底？
- V1 单次 CSV 导入上限应固定为多少条？
- 人工校正后的模板是否立即进入模板库，还是先只作为审核资产保存？
- 后续是否需要为不同行业建立独立标签体系？
- 作者信息最终是否独立成 Author 表，还是继续作为文案资产元数据保存？
