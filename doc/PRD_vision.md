# PRD 愿景稿：AI 文案拆解与组稿系统

本文保留原 `PRD_prat1.md` 中的长期产品愿景，作为主 PRD 的背景参考。当前工程实现以 `doc/PRD.md` 的阶段规划为准。

## 1. 产品目标

构建一个面向短视频、种草、营销文案创作的 AI 辅助系统。

系统可以将大量优秀文案拆解成可复用的结构化素材，并在用户创作新文案时，提供片段检索、下一句推荐、自动组稿、文案诊断和原创改写能力。

产品最终目标不是简单复制爆款文案，而是帮助用户学习优秀文案的结构、节奏、论证方式和表达方向，生成更符合自身产品和账号风格的原创文案。

## 2. 目标用户

- 短视频运营
- 个人 IP 创作者
- 电商和私域转化团队
- 文案策划人员

## 3. 核心使用场景

- 用户收集了一批同赛道优秀文案，希望系统自动拆解并沉淀为素材库。
- 用户正在写一条新文案，希望 AI 根据已有上下文推荐下一句。
- 用户希望从文案库中选择片段，手动组合成新文案。
- 用户输入产品、人群、风格和目的后，希望 AI 自动从素材库中参考结构并生成原创文案。
- 用户写完文案后，希望 AI 诊断文案问题、给出修改建议和优化版本。

## 4. 核心功能愿景

### 4.1 文案入库

用户可以手动粘贴、批量上传文案，系统保存原始文案及基础信息。

基础字段：

- 原始文案
- 来源平台
- 来源链接
- 行业
- 账号名称
- 发布时间
- 点赞、评论、收藏、转发
- 人工备注

第一版可先支持手动录入和 CSV 上传。

### 4.2 文案拆解

系统使用 LLM 将原始文案拆解为多粒度素材。

拆解对象包括：

- 整篇文案分析
- 连续片段 span
- 单句 fragment
- 可复用结构模板

每个片段需要保留上下文信息：

- `source_copy_id`
- `sequence_order`
- `previous_fragment`
- `next_fragment`
- `before_context`
- `after_context`
- `fragment_text`
- `fragment_role`
- `position`

标签设计采用“弱标签 + 强语义检索”策略。

少量稳定标签：

- `industry`: 大行业
- `position`: 开头、中段、结尾
- `fragment_role`: 钩子、痛点、解释、转折、证明、解决方案、CTA
- `source_quality`: 高表现、低表现、人工精选
- `risk_level`: 低、中、高

不强制存储大量情绪、人群、语气标签。相关需求优先在检索时通过 query 表达。

### 4.3 素材库检索

用户可以按行业、位置、片段类型筛选素材，也可以用自然语言搜索。

示例：

- 找一些适合宝妈减脂的共情型开头。
- 找更有反差感的转折句。
- 找低压力引导私信的结尾。

检索策略：

- PostgreSQL 做结构化过滤。
- Milvus 做语义向量召回。
- LLM 或 Reranker 做候选重排。

### 4.4 手动组稿模式

用户可以在文案工作台中手动选择素材片段，组合成新文案。

页面结构建议：

- 左侧：素材库
- 中间：草稿编辑区
- 右侧：AI 助手

草稿支持：

- 添加片段
- 拖拽排序
- 手动编辑
- 替换某一句
- 收藏片段
- 删除片段
- 保存版本

草稿编辑态不实时写入 Milvus，只保存在 PostgreSQL。只有用户确认沉淀为新素材时，才生成 embedding 并进入向量库。

### 4.5 AI 推荐下一句

用户在草稿中选中当前位置后，点击“推荐下一句”。

工作流：

1. 读取当前草稿上下文。
2. 判断当前文案推进状态。
3. 推断下一句应承担的功能。
4. 用当前上下文、创作目标和功能描述检索相似案例。
5. 召回原文中相似上下文后的后续片段。
6. LLM 参考候选片段生成原创下一句。
7. 返回 3-5 个候选。

返回结果包括：

- 推荐句子
- 推荐理由
- 适合插入的位置
- 语气说明
- 原创风险提示

### 4.6 AI 自动组稿

用户输入创作需求：

- 产品
- 目标人群
- 内容目的
- 平台
- 风格
- 禁忌表达
- 文案长度

系统自动生成文案。

工作流：

1. 解析需求。
2. 生成文案策略。
3. 规划文案结构。
4. 按结构位置检索相关片段和案例。
5. 生成原创初稿。
6. 诊断评分。
7. 重写优化。
8. 原创相似度检查。
9. 输出最终版本。

系统不直接拼接原句，片段库只作为结构和表达参考。

### 4.7 文案诊断与评分

系统对用户文案进行诊断。评分不作为绝对裁判，而作为编辑辅助。

诊断维度：

- 开头吸引力
- 目标人群清晰度
- 痛点具体度
- 上下文连贯性
- 情绪共鸣
- 口播自然度
- 转化动作
- 原创风险
- 违规风险

输出方式建议弱化数字，使用分档：

- 弱
- 一般
- 强
- 高风险

同时给出具体修改建议：

- 哪一句需要改
- 为什么需要改
- 建议怎么改
- 提供替换版本

## 5. 关键风险

- LLM 拆解标签不稳定。
- 片段过碎导致文案拼接感强。
- AI 评分可信度不足。
- 生成结果与原文相似度过高。
- 检索结果语义相关但上下文不连贯。

应对方式：

- 减少强标签数量。
- 保留 `sequence_order` 和上下文窗口。
- 用 span 检索替代纯单句检索。
- 评分用于诊断，不做绝对分数。
- 最终输出强制原创改写。
- 草稿不实时同步 Milvus。

## 6. 一句话产品定义

RagAgent 是一个上下文感知的 AI 文案素材与创作系统：它把优秀文案拆成可复用的结构和片段，让用户像搭积木一样组稿，并由 AI 完成推荐、诊断和原创改写。
